# 时之笛 · 乐谱编排器 & 演奏器

给 **Switch 2《塞尔达传说：时之笛》重制版** 用的陶笛曲谱编排与自动演奏工具。

在钢琴卷帘上排好谱子，经由一块 ESP32 模拟 Switch Pro 手柄，把音符按时序送进主机——它可以本地试听，也可以直接对着游戏演奏，随时能停。

---

## 功能一览

- **钢琴卷帘排谱**：横向为时间，纵向为 17 个陶笛音高
- **每个音可独立设长度**：像 FL Studio 一样拖动音符右边缘拉伸
- **BPM / 每格时值**：4 分、8 分、16 分、32 分可切换
- **断句**：Ctrl + 左键给任意位置打断句，仅按键谱按句换行
- **仅按键谱**：把谱面渲染成按键图标，适合手动演奏、截图和打印
- **谱面库**：在线浏览别人的谱面，一键载入或下载
- **本地试听**：不接硬件也能听，遵循真实时序
- **一键演奏**：把当前谱面实时推送到主机，随时可停
- **MIDI 导入**：把已有的 MIDI 直接转成陶笛谱
- **导出**：谱面导出 JSON；按键谱导出图片（PNG）与 PDF
- **设备调试页**：23 个按键逐个测试、5 档音高试音、原始命令直发
- **固件刷入页**：应用内安装 PlatformIO / CP210x 驱动、编译并烧录
- **检查更新 + 关于页**：版本、作者、项目地址，启动自动检查新版本
- **跨平台桌面应用**：基于 Electron，Windows 打包成安装包

## 快速开始

### 一、使用安装包

1. 运行 `release\` 里的安装程序
2. 从桌面或开始菜单启动「时之笛 · 乐谱编排器」
3. 插上 ESP32，切到「固件刷入」页刷入固件（首次需要）
4. 在 Switch 上进入「更改握法/顺序」界面，等待手柄配对
5. 回到「曲谱编排」页，排谱 → 「▶ 演奏」

### 二、源码运行

```bash
npm install
npm run build
npm run electron:dev
```

### 三、自己打包

双击项目根目录的 `打包.bat`，或：

```bash
npm run build
npx electron-builder --win --x64
```

产物在 `release\`：`*-win-x64.exe` 是安装包，`win-unpacked\` 是免安装版。

> 打包脚本已内置国内镜像（npmmirror），首次会自动下载 NSIS 等工具，之后走缓存。
> 若在中文路径下编译 ESP-IDF 报 GBK 编码错误，把工程放到纯英文路径（例如 `F:\ocarina`）再打包。

## 使用说明

### 1. 曲谱编排

**顶部按钮**

| 按钮 | 作用 |
|---|---|
| 🔊 声音 | 试听/演奏时的音量开关 |
| ↶ 撤销 | 撤销上一步操作 |
| 清空 | 清掉全部音符 |
| ⧉ 复制 | 复制整份谱面 |
| ▮ 粘贴 | 粘贴谱面或键位链（支持追加） |
| ⇧ 导出 | 导出为 JSON 文件（断句一起导出） |
| ⇩ 导入 | 从 JSON 文件导入，也支持 MIDI |

**节奏区**

- **BPM**：节拍速度
- **每格**：一列代表多少时值（4/8/16/32 分音符）
- **新音长**：新放的音符默认多长
- 右侧实时显示「每格 250ms」——这是全曲时间基准
- **⧉ 复制命令**：把生成的硬件命令文本复制到剪贴板

**键位面板（左侧）**

- 列出 17 个音高及对应手柄键位
- **单击**任一音即可试听
- 面板里的「键位」页签显示人话（如 `摇杆下+L`），「命令」页签显示实际下发的 `NOTE` 命令

**钢琴卷帘（中间）**

| 操作 | 效果 |
|---|---|
| 左键点空格子 | 在该列放入音符 |
| 右键点已有音符 | 删除 |
| **Ctrl + 左键** | 加一个断句方块（任意音高都行，不写音符、不出声） |
| **Ctrl + 左键** 再点同一列 / **右键** | 取消断句 |
| 按住音符右边缘拖动 | 改变音长（会顺延到下一格） |
| 滚轮 | 左右滚动 |
| 点列号 | 设定试听/演奏的起始列 |
| 写到最后一列 | 自动再加 16 列 |

**底部按钮**

| 按钮 | 作用 |
|---|---|
| ⤒ 回到开头 | 起始列归零 |
| ▶ 试听 | 本地发声，不碰硬件 |
| ▶ 演奏 | 把谱面发到开发板，真正在游戏里弹 |
| ■ 停止 | 红色按钮，立刻中断演奏 |

### 2. 仅按键谱

把当前谱面渲染成一排按键图标，适合手动跟着弹、截图分享或打印。

- **图标**：ABXY 圆形、L/R 圆角方块、左摇杆（圆内 `L` + 外侧箭头）、十字键箭头；两个键同时按下显示为「图标 + 图标」
- **排版**：连续的音紧挨着排；中间有休止才留一个固定空档；每行居中
- **断句**：在「曲谱编排」里打断句的位置会换行，句与句之间用一条青色虚线隔开
- **试听**：点「▶ 试听」，当前按键框会提亮并自动滚到窗口中间；播放时点谱面任意位置即可停止
- **导出图片**：生成整篇 PNG（白底、深色图标）
- **导出 PDF**：直接生成 A4 横向 PDF 文件，不经过打印对话框

> 页面上方会显示「N 个音 · N 处断句」。

### 3. 谱面库

在线浏览别人做好的谱面。

- 列表显示标题、作者、音符数；顶部可搜索
- 点某一首 → 弹窗里选：
  - **下载到本地**：存成 `标题_作者.json`
  - **发送到编辑器**：直接载入到「曲谱编排」（会先问一句是否替换当前谱面）
- **刷新**：强制绕过缓存重新拉取（刚上传的谱面也能立刻看到）
- 启动软件时会自动静默刷新一次
- 读取失败会提示「网络问题，暂时读不到谱面库」，不会显示过期的旧列表

数据来自公开仓库 [`ocarina-scores`](https://github.com/Kukiisama/ocarina-scores)，按 **GitHub API → jsDelivr → raw** 三级依次读取。想投稿把导出的 JSON 发给作者即可。

### 4. 设备与测试

用来排查硬件，不排谱也能用。

- **日志区**：显示下发命令与固件回包

## 演奏时序说明（重要）

这一节解释了为什么命令里带各种「奇怪」的毫秒数。

**时间基准**

```
每格毫秒 = 60000 ÷ BPM × 4 ÷ 每格时值
```

120 BPM、每格 8 分音符 → `60000 ÷ 120 × 4 ÷ 8 = 250ms`

**按住时长**

```
命令里的按住 = 音符长度 × 每格 − 82ms
```

减去 82ms 是因为固件每下发一个音符，在松开后还有一段「释放窗口」，实测固定开销约 80–85ms。不扣掉的话每个音都会晚一点，越密越明显。

**释放窗口 64ms**

两次按键之间必须让主机看到「抬起」。实测低于 16ms 会被当成一次长按（吞音），64ms 稳定。演奏前会自动下发：

```
CFG INPUT 16 64 1800
```

**换气 6 秒**

游戏里林克连续吹奏累计 **6 秒**会强制换气，第 7 秒开始的那个音会被掐掉。所以生成命令时按「连续发声时长」累计：

- 累计即将超过 6000ms 时，自动插入 **200ms** 的休止
- 谱面本身有 ≥200ms 空隙时视为已经换过气，不额外插

**蓝牙发送超时 400ms（不要调大）**

固件的发送确认超时保持 400ms。曾经试过把它放宽到 1200ms 来对抗「隔一会儿第一下失败」，结果**适得其反**：

- 心跳每 15ms 一次，一次发送卡住等 1.2 秒会让心跳断掉
- 主机判定手柄失联，之后**永久拒收**我们的输入报告（`reason=8`）
- 表现为：在配对界面一切正常，一退出配对界面就全部失败

结论：这个超时必须短。偶发的单帧失败由固件内部重试处理，上层桥接不要因此中断整条命令。

## 固件

**硬件**：ESP32（WROOM-32 / ESP-32S），通过 **Bluetooth Classic HID** 模拟 Switch Pro 手柄。

**编译环境**：`esp32dev_wireless_switch2`

```bash
cd firmware/esp32
pio run -e esp32dev_wireless_switch2
pio run -e esp32dev_wireless_switch2 -t upload --upload-port COM3
```

**串口协议（115200 8N1，每条一行）**

| 命令 | 说明 |
|---|---|
| `I` | 查询连接状态 |
| `NOTE <按键> <档位> <毫秒>` | 陶笛音符：按键 + 摇杆/十字档位（-2…+2）按住指定时长 |
| `BTN <按键>` | 按一下（可 `A+B` 组合） |
| `HOLD <按键> <毫秒>` | 按住指定时长 |
| `TAP <按键> <次数>` | 连击 |
| `STICK <x> <y> <毫秒>` | 摇杆推向指定方向 |
| `CFG INPUT <按下> <静默> <Home>` | 设置按键保持、释放静默、Home 时长 |
| `<数字>ms` | 纯等待，如 `250ms` |
| `BT RESET` | 重置蓝牙配对 |
| `BT DISCONNECT` | 主动断开主机（主机上会显示手柄已断开，配对保留） |
| `BT CONNECT` | 主动回连上次的主机 |

**档位映射（`NOTE` 命令）**

| 档位 | 实际输入 |
|---|---|
| -2 | 左摇杆推到最下 |
| -1 | 十字键 Down |
| 0 | 只按字母键 |
| +1 | 十字键 Up |
| +2 | 左摇杆推到最上 |

## 常见问题

**Q：连按同一个键，偶尔有音被吞掉？**
释放窗口不够。演奏前已自动设成 64ms；如果还偶发，说明链路拥塞，可以再调大（代价是每个音会被稍微推后）。

**Q：高音/低音听起来不对（跑调）？**
先确认键位表——「上/下」是十字键，「摇杆上/下」是左摇杆，两者不是一回事。可以用「设备与测试」页的五个档位逐个试听，对比游戏内表现。

**Q：连续几个长音，最后那个音没声音？**
换气机制。连续发声满 6 秒林克必须换气，工具会自动插 200ms 休止；如果你手动删掉了那段 `200ms`，就会重新被掐。

**Q：点「开始刷入」一直没反应？**
多数是串口被占用。先回「设备与测试」点「断开」，或重启一次应用。

**Q：提示找不到 PlatformIO？**
点固件页的「安装 PlatformIO」，或手动设置环境变量 `PLATFORMIO_BIN` 指向 `pio.exe`。

**Q：插上板子没有 COM 口？**
装 CP210x / CH340 驱动；换一根**能传数据**的 USB 线（很多线只供电）。

**Q：关掉软件后，主机上还挂着手柄？**
点「断开」时会先让开发板断开与主机的蓝牙链路，再释放串口。
如果只关了软件没点断开，可以在「设备与测试」点「回连主机」重新接回来，或者直接拔插板子。

**Q：Electron 启动后闪一下就没了？**
先看 `%TEMP%\ocarina-startup.log` 的最后几行。若是系统里有残留进程占着串口/端口，重启电脑通常能解决。

## 踩坑记录（改固件前必读）

这几条都是实测踩出来的，改动前请先读：

### 1. 右摇杆的字节编码不要动

Switch 的 `0x30` 报告里，右摇杆是 **12 位定点**，中位是 `0x800`：

```cpp
report30_[8] = (rightStickX << 4) & 0xF0;   // 中位 0x80 → 0x00
report30_[9] = (rightStickX & 0xF0) >> 4;   // → 0x08
report30_[10] = rightStickY;                // → 0x80
```

改成「标准 8 位两字节」或「12 位重新打包」都会让主机解出错误的摇杆值，表现为**视角自己高速旋转**，而且会连带触发下面第 2 条的拥塞。

定位这种问题不要靠猜，做一个「每 6 秒轮换一组候选字节」的诊断固件，观察哪一组视角静止，一次就能测出来。

### 2. 发送确认超时必须保持 400ms

`HID_SEND_REPORT_TIMEOUT_MS` 曾经放宽到 1200ms 来对抗「隔一会儿第一下失败」，结果适得其反：

- 心跳每 15ms 一次，单次发送卡住 1.2 秒会让心跳断掉
- 主机判定手柄失联，之后**永久拒收**输入报告（`status=1 reason=8`）
- 现象：在配对界面一切正常，一退出配对界面就全部失败

### 3. sniff 省电模式会导致发送永久卡死

主机空闲后会把链路切进 sniff（日志里 `bt mode-change mode=2`），此后我们的报告收不到确认，固件尝试退出 sniff 也会被拒（`status 0x10`）。

固件里已经加了自动自愈：**超过 2.5 秒没收到主机确认，就自动重启蓝牙栈并回连**（等价于手动发 `BT RESET LAST-PEER`），冷却 15 秒。用户会感觉到约 2–3 秒停顿。

手动恢复：在设备页命令框发 `BT RESET LAST-PEER`，等 5–10 秒会自动连回来，**不需要重新配对**。

### 4. 串口占用导致刷不进去

同一个 COM 口同时只能被一个进程打开。如果刷写报 `Access denied` / `Opening COM3: Access denied`，先确认没有其它 Electron 窗口、浏览器页面或后台服务占着端口。
